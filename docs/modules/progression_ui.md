# Progression UI: the Journey Book (`progression_ui`)

All of the progression screens live in one tabbed, full-screen book:

| Tab | What it is | Opens with |
|---|---|---|
| **SKILLS** | Bending skill tree (techniques by tier and branch), learning with skill points, a 4-slot loadout plus the signature slot, a live preview of each technique on the player's own rig | `open_skills` (K), pause-menu row |
| **MAP** | Parchment world map with an explored-area mask, hand-lettered regions and seas, places, ferry routes, quest markers, the player and the companion, zoom and pan, and fast travel | `open_map` (M, pad View/Back), touch top-bar Map, pause-menu row |
| **JOURNAL** | Active and completed quests, the stage log, objectives with counts, rewards, track / untrack, show on map, abandon (side quests only) | `open_journal` (J), touch top-bar Journal, pause-menu row |
| **INVENTORY** | Items by category (use herbs and food), the purse, and a **Discoveries** view (places found per region) | tabs, pause-menu row |
| **CHARACTER** | Portrait, level, XP bar, skill points, body and bending stats, mastery, journey record, companion bond | tabs, pause-menu row |

Outside the book: a **level-up banner** over the HUD that prompts you to spend the new skill point, and a **journey row** on the pause menu.

Code: `src/ui/progression/` (book, skills, character, banner, world hook), `src/ui/map/`, `src/ui/journal/`,
`src/ui/inventory/`, scene `scenes/ui/journey_book.tscn`, icons `assets/ui/icon_*.svg`,
`assets/ui/map_*.svg` and `assets/ui/ui_close.svg` (generated by
`assets/ui/authoring/make_progression_icons.py`).

## Quick start (other modules)

```gdscript
# The world scene gets the book through WorldHooks (src/ui/progression/world_hook.gd). Anywhere else:
var book: JourneyBook = preload("res://scenes/ui/journey_book.tscn").instantiate()
scene.add_child(book)

book.open(&"map")                                  # -> bool (false + book.blocked_reason() when refused)
book.open(&"map", {"npc": &"master_pakku"})        # pin and focus an NPC (e.g. "find your master")
book.open(&"map", {"quest": &"wt_first_form"})     # focus a quest's marker
book.open(&"map", {"place": &"omashu"})            # focus a place and show its card
book.open(&"journal")
book.close()
book.toggle(&"skills")
book.show_page(&"character")                       # switch tab while open
JourneyBook.opened / closed / page_changed         # signals

# Data without UI
SkillTreeModel.learn(&"ice_trap")                  # spends the cost, unlocks, refreshes the player's loadout
SkillTreeModel.equip(2, &"ice_trap")               # slot 0..3, swaps if it was elsewhere
MapModel.travel(MapModel.place_by_id(&"port_full_moon_bay"))   # await; guard rails apply
MapModel.reveal(world_pos, 300.0)                  # mark an area explored
CompanionBond.tier()                               # {"index", "name", "from", "to"}
```

Group hooks (no code needed in other modules): the book joins `journey_book` (the pause menu
looks for it), `map_screen` and `journal_screen` (the touch overlay's top bar shows Map and
Journal only when these exist; its buttons press `open_map` / `open_journal`).

## The book (`JourneyBook`, CanvasLayer 80)

* **Pauses** the tree while open (`get_tree().paused`, `Events.pause_changed`), shows the
  mouse, releases every held gameplay action (so nothing is "stuck" when it closes), blurs and
  dims the world behind the sheet. Everything in the book runs `PROCESS_MODE_ALWAYS`.
* **Closes** with Esc / pad B / the Android back button (`ui_cancel`), the page's own action
  again (M on the map), the CLOSE button, or a click or tap outside the sheet. A page may use
  Back first (the skills page leaves "choose a slot" before closing). Opened from the pause
  menu, closing goes back to the pause menu.
* **Never traps input**: `blocked_reason()` refuses to open while the world is not ready,
  during scene transitions, with no journey, while dead, in a cinematic, while travelling, in
  dialogue, in a shop, or while another pause is up. Dialogue start, death, returning to menu
  and Router transitions close it.
* **Tabs**: Q / E, LB / RB, click or tap. Confirmations use `ConfirmDialog` (`book.confirm()`).
* Pages are `JourneyPage` controls built lazily on first show (`_build`, `on_open(args)`,
  `on_close`, `initial_focus`, `hints`, `handle_back`, `handle_input`, `page_process`).
* Input routing: `open_*` while closed go through `_unhandled_input`; while open the book uses
  `_input` for back/tabs because the pause menu sits later in the tree. Modal `UiOverlay`s
  (confirm dialogs) get input first.

## Skills page

**Layout.** Tiers run left to right (I to IV, each tier shows the level it needs), branches run
top to bottom with their names (Ice / Flow / Healing, Stone / Seismic / Guard, Breath / Flame /
Lightning, Gale / Circle / Flight). The layout comes from each kit's `AbilityDef.unlock`
(`tier`, `branch`, `column`). The "core kit" column on the left lists the always-known moves
(light, heavy, defense, dodge, innate). Connectors are tapered brush strokes: lit when learned,
gold when the next technique is ready to learn, dim otherwise.

**Node states.** Learned (element colour), available (gold ring, ready to learn), locked
(padlock; a master's seal on trainer-taught techniques). The slot number shows on equipped
techniques.

**Details panel.** A live preview (below), name, kind, tier, chi, cooldown, damage, statuses,
description and **requirements** with a tick or cross each, in `AbilityRegistry.can_unlock`
order: level, prerequisite, trainer, quest, practice of the prerequisite, skill points. The
action buttons depend on state: LEARN · n SKILL POINTS, EQUIP / MOVE TO ANOTHER SLOT, UNEQUIP,
FIND <MASTER> ON THE MAP (opens the map with a pin on the trainer, found through
`NpcRegistry`).
Trainer techniques are paid for with the lesson (`TrainerLessons`), so no point cost is shown.

**Learning.** `SkillTreeModel.learn(id)` checks `can_unlock`, spends `unlock.cost` (default 1,
starters 0), calls `GameState.unlock_ability`, records `techniques_learned`, and reloads the
live player's loadout (`BendingController.load_equipped()`). The UI asks for confirmation.

**Equipping.** Four technique slots plus the signature slot. The signature is automatic: the
element's first learned SIGNATURE technique (that is how `BendingController` loads it).
* Mouse: drag a learned technique onto a slot, drag a slot onto another to swap, drag a slot
  off the bar to unequip; or click a technique (it is "armed") then click a slot.
* Keyboard: Enter on a technique arms it, arrows to a slot, Enter places it; 1 to 4 put the
  focused technique straight into that slot; Delete / Backspace on a slot unequips it.
* Pad: A arms, d-pad to the slot, A places; X on a slot unequips; B cancels the arming.
* Touch: tap a technique, then tap a slot (no drag on touch).
`GameState.equip_ability` swaps when the technique was in another slot; the player's loadout
reloads at once, so the HUD shows the change when the book closes.

**Live preview (`TechniquePreview`).** The player's own `HumanoidRig` (element preset, style,
appearance) in a `SubViewport` with its own World3D and staging lights, playing the same
`AnimLibrary` clips the ability plays: the combo steps for light strikes; tap, hold and release
for heavy and charged moves; the dodge clips; the defense hold; the technique's hold and cast
clip. `PreviewFlourish` adds element-coloured particle bursts, a travelling bolt with a trail,
and ground rings on the clips' timed events (release / impact / gather ...). These are
presentation-only stand-ins: the real ability VFX in `src/fx` spawn under the current scene's
FxRoot and need a real target, so they can't run inside the preview world. The viewport renders
only while visible and is sized to the control (capped at 1.25x).

## Map page

**Data (`MapModel`, no UI).**

* Coordinates follow `WorldData.world_to_map_uv` / `map_uv_to_world` (8192 m square, north = -Z).
* `places()`: cities, villages, ports and POIs as `{id, kind, type, name, region, position,
  radius, description, icon}`. Records that are the same place are merged so each place has
  one marker. A village / port and the discovery POI on the same spot (village to `village`,
  camp to `camp`, port to `dock`, within 140 m) share one marker: the POI gets `merged_into` and
  the record gets `twin`. A harbour town and its port with the same name share the port's
  marker (`absorbs`). `shown_place(p)` maps a merged place to its marker.
* Knowledge: cities are always lettered, but only the home city is *known* until you visit
  one. Villages and ports are known once visited or once their twin POI is discovered. POIs
  are known once discovered.
* Saved state (in `GameState.world_flags`, saved with no extra code):
  * `"visited_places"`: `{place_id: true}`. Walking into a city, village or port radius marks it.
  * `"map_reveal"`: base64 bitset, 128 x 128 cells of 64 m, row-major north to south. 320 m
    around the walking player (sampled at 1 Hz), 260 m around each discovered POI. It is
    seeded for new and older saves from the home city, discoveries and visits.
    `revealed_ratio()` gives "% of the world explored".
* Fast travel: travel points are known cities, villages and ports, plus known shrines,
  training grounds, village POIs and docks. `travel_block_reason(p)` returns `""` or one of
  these: "Discover this place first.", "Not in the training grounds.", "Not while enemies are
  near." (`EncounterDirector.in_combat`), "Not now." (dead), "You are already here." (< 60 m),
  "Fast travel is not available here." (no world scene / TravelSystem), "Already travelling.".
  `travel(p)` calls the world scene's `TravelSystem.travel_to(transform, {text})` (the same
  fade and streaming hold as ferries) and records `fast_travels`. Landing spots: the home
  city's spawn, otherwise just outside a city gate; a port's quay
  (`TravelSystem.quay_transform`); otherwise safe ground beside the place. The companion
  follows on its own (it teleports when more than 110 m away).

**Drawing.** `MapCanvas` draws the parchment texture (`WorldData.get_map_texture`) through
`map_fog.gdshader`: unexplored paper is sepia-washed, with a noisy inked edge. `MapOverlay`
draws ferry routes (dashed, with a boat glyph), region and sea lettering (with the nation's
seal glyph; it fades as you zoom in), places (dotted "?" marks for undiscovered POIs; a disc
and icon once known; a gold gate badge on travel points), quest objectives (tracked ones
pulse) and quest givers (from zoom 1.8), a pin, the companion (paw) and the player arrow
(heading). Labels go through a placement pass: priority order, below or above the marker,
kept inside the map and off the info panel, buttons and scale bar, dropped when they would
overlap (except hovered or selected ones). A scale bar sits bottom-left.

**Input.** Mouse: wheel zooms at the cursor, drag pans, click selects, double-click (or the
card's button) travels. Touch: one-finger drag pans, pinch zooms, tap selects; the on-map
+, - and centre buttons are 72+ px. Mouse events emulated from touch are ignored, so a finger
is never counted twice. Pad / keyboard: the left stick or WASD moves a reticle that snaps to
markers (the view follows at the edges); RT / LT or + / - zoom; A / Enter travels or opens the
quest; Y / C centres on you. The card shows the place's name, type, state (visited, discovered,
undiscovered), distance and bearing, the description, FAST TRAVEL or the reason it's
unavailable, and OPEN IN JOURNAL for quest markers. Fast travel asks for confirmation first.

## Journal page

Binds to the `Quests` journal API (`docs/modules/quests_npcs.md`): `Quests.journal(filter)`,
`journal_entry`, `state`, `is_active`, `get_def`, `track`, `abandon`, `map_markers` and the
`quest_changed` signal, so the page refreshes live. Rows show a kind seal (main / side / trainer), title, giver location, stage n of
total and TRACKED. The parchment page shows the nation seal, giver and location, summary, the
current stage's objectives (checkbox and count), earlier stages (newest first) and rewards.
Enter / A on a row tracks or untracks it (so does T). Tab switches between active and completed.
The map key (`open_map`: M, pad View) or pad Y opens the map on the quest's marker. Pad X or
the ABANDON button abandons a side quest, after confirmation.

## Inventory page

Items view: category filters, tiles (`ItemIcon`, count badge), details (icon, name, category,
origin, count, description, effect, value and what a merchant pays), and USE for herbs, food
and drink (`TradeGoods.use_item` on the live player, refused at full health). The first click
or tap on a tile selects it and a second press uses it. Enter / A on a focused tile uses it.
The Discoveries view (Tab / Y) lists discovered places per region with progress bars. The
purse shows `GameState.currency`.

## Character page

Portrait (the same preview rig, idle, slowly turning), name, title and tagline, level seal,
XP bar ("x / need XP · n to level k (+1 skill point)"), skill points, **body and bending**
stats read from the live player (health, chi, focus, poise, run and sprint speeds, the element's
movement trait, dodge distance and i-frames, air jumps, knockback taken), **mastery** (techniques
learned, signature, most practised), **the journey so far** (time on the road, places discovered,
world explored %, quests completed, enemies defeated, camps cleared, lessons, spars,
techniques used, coins) and the **companion** with its bond.

`CompanionBond`: points = rides x 5 + km ridden x 10 + km flown x 8 + hours together x 6
(capped at 1000). Rides and distances come from `GameState.stats` (`companion_rides`,
`companion_ridden_m`, `companion_flown_m`, counted by the companions module). Hours together is
the journey's play time, since the companion travels with you from the start. Tiers: New Companion 0, Familiar 60, Trusted 160,
Devoted 340, Kindred Spirits 600. `sync()` stores the points in `GameState.companion["bond"]`
(the world hook calls it every second). It's a record for now; no gameplay reads it yet.

## Level-up flow

`LevelUpBanner` (CanvasLayer 38, above the HUD) listens to `Events.player_level_up`. Several
level-ups in the same frame are combined into one banner showing the highest level. The
banner shows a brush stroke, LEVEL n, "+1 Skill Point · n to spend", "Ready to learn: ..."
(techniques the new level opens), and a prompt to open the skills page: the K glyph on
keyboard, "Pause · Skills" on a pad (no pad binding for open_skills), or an OPEN SKILLS button
on touch. It hides when the book opens. The tab bar's level seal and points label refresh live.

## World hook and pause menu

`src/ui/progression/world_hook.gd` (installed through `WorldHooks.HOOK_PATHS`, skipped in the
training grounds): adds the book (disabled until `world_ready`, so it can't open over the arrival
cinematic) and the banner, seeds the map mask on spawn, notes the player's position at 1 Hz
(visits and reveal), reveals around each `poi_discovered`, and syncs the companion bond.

Pause menu: a row of five buttons (SKILLS, MAP, JOURNAL, INVENTORY, CHARACTER), shown only
when the scene has an enabled JourneyBook. A button resumes the pause menu's own pause and
opens the book, and closing the book returns to the pause menu.

## Decisions

* **One book, five tabs**, not five separate screens: one pause / close / input contract, one
  place where "never trap input" is enforced, and tabs to move between related screens
  (the journal's SHOW ON MAP, the skills page's FIND THE MASTER).
* **Rules stay in their owners**: the tree asks `AbilityRegistry.can_unlock`, learns through
  `GameState.unlock_ability`, equips through `GameState.equip_ability` and reloads through
  `BendingController.load_equipped()`. Quests come from the `Quests` API, items from
  `TradeGoods`, fast travel from `TravelSystem.travel_to`. The UI keeps no copies.
* **Map state in world flags** (visited places, explored mask): it saves and loads with the
  existing save code, and older saves are seeded on first open.
* **Merged markers**: settlement records and discovery POIs describe the same places, so the
  map shows one marker each; discovery state still comes from the POI.
* **Preview flourish instead of real VFX**: the real effects depend on the scene's FxRoot,
  targets and physics. The preview plays the real animation clips and uses lightweight
  stand-in effects timed to the clips' events.
* **Signature slot is automatic** (one signature technique per element in every kit), so it is
  shown but cannot be dragged into.

  matching `can_unlock`; learning spends points; equip, swap and refusals; live player reload;
  learn, arm and equip on the page, drag-and-drop data and focus navigation; map coordinate

  explored mask surviving a JSON save round trip; the map card and travel confirmation; the

    the full tree is shown; the game pauses; the preview plays the technique's clips and its
    effects fire; a real mouse drag from the tree onto slot 4 equips; Enter plus confirm learns
    and spends a point; key 1 quick-equips; Delete unequips; a locked node explains itself; Esc
    closes and the player's slot 1 matches. Passed at 1920x1080 and 1280x720 (water and fire).

    journey row; journal opened from pause; Enter tracks; Tab shows completed; SHOW ON MAP
    focuses the quest; inventory tiles and Enter uses an herb; discoveries; character; Esc
    returns to the pause menu, then resumes. Passed at 1920x1080 and 1280x720.

## Known issues / next steps

* The book isn't installed in the training grounds (tutorial), on purpose: that scene has no
  journey to show.
* The combat arena flattens `WorldData`. Map, discoveries and fast travel need the real world
  data (`WorldData.use_flat_world(false)`, as the arena playtests do) and a world scene for
  travel.
* Preview effects are stand-ins (see Decisions). The real ability VFX are seen in play.
* `open_skills` and `open_journal` have no pad binding by default (the pad reaches them through
  View (map), then LB / RB, or the pause-menu row). Rebindable in Settings.
* The companion bond is a record; no gameplay effect reads it yet.
* Tested on desktop resolutions and a simulated phone (touch events, mobile renderer). Not
  tested on a real device.
* The world-scene map playtest runs at 1280x720 because 1920x1080 is too slow under the
  software renderer in CI.
